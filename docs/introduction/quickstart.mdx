# Быстрый старт

**SwingTraderAI** состоит из Python/FastAPI backend, frontend-приложения и набора инфраструктурных сервисов.

Для локального запуска проекта рекомендуется использовать **Docker Compose**. Это позволяет автоматически поднять необходимые сервисы, включая базу данных PostgreSQL, Redis и фоновые worker-процессы.

Ручной запуск отдельных компонентов возможен для разработки, но основным способом запуска проекта является Docker Compose. Потому что заставлять человека вручную поднимать несколько сервисов, базы данных и worker-процессы в 2026 году было бы несколько жестоко.

## Требования

Перед запуском убедитесь, что установлены:

\* **Docker** \* **Docker Compose** \* **Git**

Для разработки frontend и запуска отдельных компонентов напрямую также могут потребоваться:

\* **Python 3.12–3.14** \* **Poetry** \* **Node.js** \* **Yarn**

Версия Python определяется конфигурацией `pyproject.toml`:

```toml
requires-python = ">=3.12,<=3.14"
```

## 1. Клонирование репозитория

Склонируйте репозиторий и перейдите в директорию проекта:

```bash
git clone <repo-url>
cd SwingTraderAI
```

## 2. Настройка переменных окружения

Перед запуском создайте локальный файл `.env`.

Минимальный набор переменных:

```env
SECRET_KEY=replace-with-a-long-secret
ALGORITHM=HS256
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/swingtrader
REDIS_URL=redis://localhost:6379/0
ACCESS_TOKEN_EXPIRE_MINUTES=30
REFRESH_TOKEN_EXPIRE_DAYS=7
CORS_ALLOWED_ORIGINS=["http://localhost:5173"]
```

Актуальная конфигурация приложения находится в:

```text
swingtraderai/core/config.py
```

Не используйте реальные секреты, пароли или токены в Git-репозитории.

## 3. Запуск проекта для разработки

Для стандартной разработки используется Docker Compose:

```bash
docker-compose up
```

Конфигурация разработки подхватывает соответствующий override-файл автоматически.

После запуска Docker Compose поднимает необходимые сервисы проекта согласно текущей конфигурации Compose.

Основной backend использует **FastAPI**, а API-документация доступна через OpenAPI endpoint `/docs`.

При локальном запуске backend стандартно используется порт `8000`:

```text
http://localhost:8000/docs
```

## 4. Запуск тестов

Для запуска тестового окружения используются основной Compose-файл и отдельная тестовая конфигурация:

```bash
docker-compose -f docker-compose.yml -f docker-compose.test.yml up --abort-on-container-exit
```

В этом режиме запускаются необходимые инфраструктурные сервисы, включая:

\* PostgreSQL; \* Redis; \* тестовый сервис проекта.

Флаг `--abort-on-container-exit` завершает Compose после завершения тестового контейнера.

Это удобно для CI/CD и автоматической проверки проекта.

## 5. Запуск production

Production-окружение запускается с использованием отдельной конфигурации:

```bash
docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

Использование `-d` запускает контейнеры в фоновом режиме.

Production-конфигурация предназначена для запуска оптимизированных образов без режима разработки и автоматической пересборки на лету.

## 6. Структура Compose-конфигурации

Проект использует несколько Compose-файлов для разных сценариев:

```text
docker-compose.yml
docker-compose.test.yml
docker-compose.prod.yml
```

Их назначение:

| Конфигурация | Назначение |
| --- | --- |
| `docker-compose.yml` | Основная конфигурация проекта |
| `docker-compose.test.yml` | Тестовое окружение |
| `docker-compose.prod.yml` | Production-окружение |
| Override-конфигурация | Локальная разработка |

Такой подход позволяет использовать общую инфраструктуру проекта и изменять только необходимые параметры для конкретного окружения.

## 7. Ручной запуск backend

Docker Compose является рекомендуемым способом запуска проекта, однако backend можно запустить непосредственно из Python-окружения.

Установите зависимости через Poetry:

```bash
poetry install
```

Затем запустите FastAPI:

```bash
uvicorn swingtraderai.main:app --reload --host 0.0.0.0 --port 8000
```

После запуска API-документация будет доступна по адресу:

```text
http://localhost:8000/docs
```

При таком варианте PostgreSQL, Redis и другие необходимые сервисы всё равно должны быть доступны приложению.

## 8. Frontend

Frontend расположен в отдельной директории:

```text
frontend/
```

Для его самостоятельного запуска:

```bash
cd frontend
yarn install
yarn dev
```

Frontend и backend являются отдельными частями системы и взаимодействуют через API.

## 9. Миграции базы данных

Проект использует **Alembic** для управления миграциями базы данных.

Для применения всех доступных миграций:

```bash
alembic upgrade head
```

При запуске через Docker Compose миграции могут выполняться в рамках соответствующего сценария запуска, в зависимости от текущей конфигурации контейнеров.

## 10. Основные команды

### Разработка

```bash
docker-compose up
```

### Тестирование

```bash
docker-compose -f docker-compose.yml -f docker-compose.test.yml up --abort-on-container-exit
```

### Production

```bash
docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

## Важные замечания

\* **Docker Compose является основным способом запуска проекта.** \* Backend построен на **FastAPI**. \* Для работы с базой данных используется **PostgreSQL** через SQLAlchemy и `asyncpg`. \* **Redis** используется инфраструктурой проекта и связан с фоновыми задачами. \* Для фоновой обработки предусмотрен **Celery**. \* Frontend находится отдельно в директории `frontend/`. \* Для управления миграциями базы данных используется **Alembic**. \* ML-компоненты проекта используют `scikit-learn`, `XGBoost` и связанные библиотеки. \* Проект также содержит компоненты для работы с рыночными данными, включая `yfinance`, `ccxt` и `moexalgo`. \* Наличие ML, AI и фоновых worker-компонентов не означает наличие полноценной системы автоматического исполнения сделок через брокера.

## Рекомендуемый порядок запуска

Для обычной разработки достаточно:

```bash
git clone <repo-url>
cd SwingTraderAI
docker-compose up
```

После успешного запуска проверьте API через:

```text
http://localhost:8000/docs
```

Если требуется проверить проект в тестовом окружении:

```bash
docker-compose -f docker-compose.yml -f docker-compose.test.yml up --abort-on-container-exit
```

Для production:

```bash
docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```
